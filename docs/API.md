# PARADOX API, contract 1.0.0

For frontend development. Types are in [shared/types/paradox.ts](../shared/types/paradox.ts). Every
route has a real request and response in [shared/fixtures/](../shared/fixtures/), generated by the
formal model with `make fixtures`, so you can build a mock backend directly from those files.

Start the app with `make run`. It listens on `http://127.0.0.1:8787`, serves the UI from `web/` at
`/`, and allows API requests from any origin. To work on the UI, run `npm run dev` in `apps/frontend`.

## Rules for the frontend

1. **The backend decides what happens.** You may interpolate between frames for drawing. Do not
   compute physics.
2. **Send worlds back exactly as you received them.** The API keeps no state. Each request carries
   the whole world.
3. **Use `renderPosition`, `renderVelocity` and `renderSize` for drawing only.** They are floating
   point. The exact values are the rational strings, such as `"49/10"`.
4. **Show `unknown` as not established, never as a failure.**
5. **Show `assumptions`, `scope` and `doesNotSay`.** A theorem must not look wider than it is.

## Statuses

| Status | Meaning | Suggested label |
|---|---|---|
| `proven` | Lean checked a theorem establishing this, under the listed assumptions and scope. | Consistent |
| `counterexample` | A concrete run, replayed through the formal model, breaks the claim. | Counterexample |
| `unknown` | Neither was established. | Unproven |
| `underspecified` | Required behaviour is missing, so the simulation relies on a default. | Underspecified |
| `inconsistent` | No universe with at least one object can meet these requirements. | Contradiction found |

## Scopes

| Scope | Covers |
|---|---|
| `allowed` | Only events a protected universe permits. |
| `any` | Every event that can be written down. |
| `timeOnly` | No events: time passes and the laws run. |

## Routes

Errors return status 400 or 404 with `{ "error": "message" }`.

### Discovery

| Route | Returns |
|---|---|
| `GET /api/health` | Status, contract version and the list of routes. |
| `GET /api/theorems` | Each theorem: `id`, `layer`, `statement`, `assumptions`, `doesNotSay`. |
| `GET /api/presets` | Each preset: `name`, `title`, `description`. |

### Creating and running a universe

| Route | Request | Returns |
|---|---|---|
| `POST /api/universe/create` | `preset?`, `seed?` | `world`, `preset`, `seed`, `guaranteed` |
| `POST /api/universe/step` | `world`, `event`, `mode?`, `constraints?` | `world`, `mode`, `decision`, `frozen`, `violations`, `brokenConstraints` |
| `POST /api/universe/run` | `world`, `steps?`, `events?`, `mode?`, `constraints?`, `chaos?`, `frameEvery?` | `frames`, `world`, `guarantees`, `nextChaosSeed` |

- `mode` is `"protected"` or `"unprotected"`, and defaults to unprotected.
- In `run`, events are applied first, one per step. Remaining steps are `idle`.
- `frameEvery` sets how often a frame is sent. Default 1.
- `decision` is `accepted`, `repaired` or `rejected`. Show `original` beside `event` when repaired.
- `constraints` apply in protected mode only. `frozen: true` means the world refused the change.
- `violations` reports which guarantees are false now. In unprotected mode this can be non-empty.
- Each frame's `guarantees` gives every guarantee's status in that exact state. `proven` means the
  theorem covers every permitted future from here. `unknown` means it holds now but the theorem's
  conditions do not. `violated` means this state breaks it.
- `chaos` adds a reproducible chance of a random event each step: `{ seed, rate, kind }`, where `rate`
  is out of 1000. Send `nextChaosSeed` as the next `seed` to carry on the same experiment. Safe chaos
  is proved permitted for every seed and rate. Wild chaos may break the rules.

**Playing a universe:** request 30 to 60 steps at a time and interpolate between frames. A universe
of about 10 bodies runs at roughly 1,300 steps per second on an M-series Mac.

### The Consistency Inspector

`POST /api/universe/check-consistency` takes `world`, `constraints?`, `properties?`, `limits?` and
returns all three layers:

| Field | Question | Statuses |
|---|---|---|
| `ruleConsistency` | Can the constraints all hold in a universe with at least one object? | `proven` with a `witness`, `inconsistent` with a `conflict`, `unknown` |
| `transitionConsistency` | Do the rules say what happens next, without relying on a default? | `proven`, `underspecified`, `counterexample` for rule-order conflicts, `unknown` |
| `evolutionConsistency` | Do guarantees survive as the universe changes? | one `Verdict` per claim |

Every result has `checked` or `assumptions`, so you can state what was checked.

`transitionConsistency.deterministic` is always true: the rule list fixes the order. `ruleConflicts`
lists rule pairs that would give different results in the other order.

### The Proof Explorer

| Route | Request | Returns |
|---|---|---|
| `POST /api/universe/verify-property` | `world`, then `property`, `claim`, `properties` or `claims`, and `limits?` | `verdicts` |
| `POST /api/universe/find-counterexample` | `world`, `property` or `claim`, `scope?`, `limits?` | `status`, `checked`, `scope`, `counterexample` |
| `POST /api/universe/check-trace` | `trace`, `claim`, `scope?` | `valid`, `replays`, `inScope`, `breaksClaim` |
| `POST /api/universe/audit-laws` | `world`, `limits?` | `mass`, `energy`, `population`, `momentumBetweenBodies`, `momentumFullStep` |

`verify-property` only searches permitted events. To show what breaks in an unprotected universe,
call `find-counterexample` with `"scope": "any"` (the default for that route).

**Replaying a counterexample:** draw `trace.initial`, then each entry of `trace.states`. Each state
is what the formal model produced after the matching entry of `trace.events`.

### The Rule Editor

| Route | Request | Returns |
|---|---|---|
| `POST /api/universe/validate-rules` | `rule` or `rules`, `world?` | One report per rule: `status`, `certified`, `keeps`, `missingRegions`, `repair`, `explanation` |
| `POST /api/universe/check-event` | `world`, `event` | `allowed`, `decision` |
| `POST /api/universe/check-formula` | `formula`, `massA?`, `massB?`, `chargeA?`, `chargeB?`, `speedSquared?`, `rMax?` | `status`, `explanation`, `samples` |

Rules and force laws are data. See `Rule` and `LawExpr` in the types file. The API never runs code
from a request.

### Experiments

`POST /api/universe/random-events` takes `seed`, `count`, `kind?` (`"safe"` or `"wild"`) and returns
`events`. The same seed always gives the same events. `"safe"` events are proved permitted for every
seed. `"wild"` events may break the rules, for unprotected experiments.

## Examples of invented laws

Newton-style attraction, as a `pairForce` (the result multiplies the line between the bodies):

```json
{ "type": "div",
  "a": { "type": "mul", "a": { "type": "const", "value": "20" },
         "b": { "type": "mul", "a": { "type": "massA" }, "b": { "type": "massB" } } },
  "b": { "type": "add", "a": { "type": "const", "value": "1/10" },
         "b": { "type": "mul", "a": { "type": "distSquared" }, "b": { "type": "dist" } } } }
```

Objects get heavier as they move faster, as a rule. The checker proves this keeps mass positive:

```json
{ "type": "body",
  "action": { "type": "setMassFormula",
    "formula": { "type": "add", "a": { "type": "const", "value": "1" },
      "b": { "type": "mul", "a": { "type": "const", "value": "1/100" },
             "b": { "type": "speedSquared" } } } } }
```

## Limits

| Limit | Value |
|---|---|
| Bodies in a world | 256 |
| Steps or events per request | 5,000 |
| Bodies² × steps per request | 5,000,000 |
| Pieces in one formula or rule | 256 |
| Stacked powers in one formula | 2 |
| Request size | 8 MB |
| Search depth, budget, idle steps | 5, 20,000, 2,000 |

Search limits are lowered automatically for large worlds. A lower limit can turn a counterexample
into `unknown`, but it cannot make any answer wrong.

**Do not set `grid` to 0 for long runs.** With no grid, exact rationals can grow without limit, and
each step gets slower. The default is 4096.

## Changing the contract

Agree changes between both developers, change `contractVersion` in `Paradox/Api/Routes.lean`, update
the types file, and regenerate fixtures.
